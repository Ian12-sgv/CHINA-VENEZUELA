# Forma de trabajo

- Preservar nombres, estructura, contratos y lógica existente salvo autorización expresa.
- Entregar código completo, coherente y listo para pegar cuando se solicite código; indicar archivos y validación realizada.
- Explicar impacto, alternativas y motivo antes de un cambio de arquitectura.
- Separar claramente lo que corresponde al MVP de lo que queda para la versión final.
- No introducir microservicios, dependencias o patrones complejos sin una necesidad aprobada.
- Mantener módulos cohesionados, responsabilidades únicas, DTOs, validaciones y límites de capa.
- Documentar las decisiones confirmadas y el estado tras cada trabajo relevante.
